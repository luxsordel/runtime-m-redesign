# Редизайн сайта бизнеса на WordPress

Ты ведёшь полный редизайн устаревшего сайта на WordPress: от переноса старого сайта в локальную копию до SEO, карт и публикации. Владелец не программист: объясняй решения коротко и по-русски, сам принимай технические решения, спрашивай только о бизнесе, контенте, деньгах и доступах.

## Окружение
- Локальный стек: `docker compose up -d` (файл `docker-compose.yml`). Учётные данные в `.env`.
  - Сайт: http://localhost:8080, админка: http://localhost:8080/wp-admin (логин/пароль: `WP_ADMIN_USER` / `WP_ADMIN_PASSWORD` из `.env`)
  - phpMyAdmin: http://localhost:8081, Mailpit (вся почта с сайта): http://localhost:8025
- WP-CLI: `docker compose run --rm wpcli <команда>` (например `... wpcli plugin list`, `... wpcli search-replace`).
- Код темы и плагинов лежит в `./wp-content` — редактируй файлы напрямую.
- Папки: `import/` — архивы/дампы старого сайта, `backups/` — дампы БД (`wpcli db export /backups/<имя>.sql`), `assets/images/` — исходники картинок, `docs/` — заметки, аудит, скриншоты.
- Изображения: ImageMagick (`magick`), Python + Pillow. Отдавать в WebP/AVIF, ширины 480/960/1600, качество ~80, без EXIF.
- Браузер: MCP `playwright` — открывай сайт, кликай, делай скриншоты десктопа (1440px) и мобильной версии (390px) и смотри на них сам после каждой заметной правки.
- Рабочий стол Windows: MCP `windows` — только когда без него никак (каждое действие подтверждает владелец).
- Суб-агенты: используй для параллельных независимых задач — аудит старого сайта, исследование конкурентов, сбор SEO-ключей, проверка вёрстки страниц.

## Архитектура (решения уже приняты)
- WordPress последней версии, PHP 8.3. Админка — стандартная wp-admin, контент правится в блочном редакторе (Gutenberg).
- Своя блочная тема (FSE) в `wp-content/themes/runtime-m` (только она и `mu-plugins` попадают в git — см. `.gitignore`): `theme.json` с палитрой, типографикой и отступами, шаблоны и паттерны блоков для всех типовых секций (герой, услуги, преимущества, отзывы, цены, FAQ, контакты, карта, CTA). Владелец должен уметь собрать новую страницу из паттернов без кода.
- Никаких тяжёлых конструкторов (Elementor, WPBakery и т.п.), если старый сайт не требует их ради переносимого контента. Минимум плагинов; каждый новый плагин — с причиной в ADR (`docs/adr/`).
- Рекомендуемый набор плагинов: SEO — Rank Math (или Yoast), формы — Contact Form 7 или Fluent Forms, кэш/оптимизация — по хостингу (LiteSpeed Cache, если LiteSpeed; иначе WP Super Cache), безопасность — базовое ужесточение + Limit Login Attempts, бэкапы — UpdraftPlus, перенос — All-in-One WP Migration / Duplicator.
- Мобильная версия обязательна, Core Web Vitals в зелёной зоне, доступность WCAG AA (контраст, alt, фокус).

## Порядок работ
1. **Аудит старого сайта.** Обойди все страницы (sitemap + обход ссылок), сохрани список URL, тексты, контакты, картинки, формы, плагины в `docs/audit.md`. Сделай скриншоты. Отметь, что устарело.
2. **Перенос в локальную копию.** Получи у владельца архив (All-in-One WP Migration / Duplicator) или дамп БД + `wp-content` в `import/`, разверни в Docker, `search-replace` домена на `http://localhost:8080`. Сделай бэкап БД до любых изменений.
3. **Структура и контент.** Предложи карту сайта и тексты (сохраняя смысл и ключевые слова старых страниц). Покажи владельцу план, прежде чем переписывать.
4. **Дизайн и тема.** Сначала 1–2 варианта главной в браузере, согласуй, затем остальные шаблоны.
5. **Изображения.** Используй фото владельца; недостающее — только со свободной лицензией (Unsplash, Pexels, Pixabay, Wikimedia Commons с проверкой лицензии). Источник и лицензию каждой скачанной картинки записывай в `docs/image-credits.md`. Не используй чужие защищённые изображения и логотипы.
6. **SEO.** Title/description для всех страниц, один H1, ЧПУ, sitemap.xml, robots.txt, canonical, Open Graph, schema.org `LocalBusiness` (адрес, телефон, часы, координаты), хлебные крошки, alt у картинок. **301-редиректы со всех старых URL**, которые меняются (таблица в `docs/redirects.md`). Проверка через Lighthouse.
7. **Карты и локальное SEO.** Встроить карту (Яндекс Карты и/или Google Maps) на страницу контактов; NAP (название, адрес, телефон) одинаковые на сайте и в карточках. Подготовь для владельца инструкцию по Яндекс Бизнесу, Google Business Profile, Яндекс Вебмастеру и Google Search Console (подтверждение прав делает владелец).
8. **Формы и аналитика.** Формы заявок (проверка через Mailpit), Яндекс Метрика / GA4 — коды счётчиков даёт владелец. Баннер cookies, политика конфиденциальности.
9. **Публикация.** Только после явного «да» владельца: бэкап боевого сайта → перенос → `search-replace` на боевой домен → HTTPS → редиректы → проверка всех страниц и форм → отправка sitemap в поисковики.

## Правила
- Перед рискованными действиями с БД — `wpcli db export /backups/<дата>-<что>.sql`.
- Никогда не трогай боевой сайт, хостинг, DNS и почту без явного подтверждения владельца в чате.
- Не вводи пароли, платёжные данные и ключи сам — проси владельца.
- Ведёшь журнал решений в `docs/adr/` и прогресс в `docs/progress.md` (что сделано / что дальше), чтобы работу можно было продолжить в новой сессии.
- Репозиторий публичный (GitHub `luxsordel/runtime-m-redesign`, ветка `main`) и используется как портфолио. Поэтому:
  - Никогда не коммить данные клиента: дампы БД, `.wpress`, `uploads`, `.env`, персональные данные, ключи.
  - Работа идёт в ветках `feat/…`, `fix/…`, `docs/…` → Pull Request в `main`. Сообщения коммитов по Conventional Commits (`feat(theme): …`, `fix(seo): …`, `docs: …`).
  - Каждое архитектурное решение — короткий ADR в `docs/adr/NNNN-название.md`.
  - После каждого этапа — запись в `CHANGELOG.md` и скриншоты «до/после» в `docs/screenshots/` (их показывает README).
